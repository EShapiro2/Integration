## What Integration is now, and what changed while I ran

Integration was created on 2026-09-16 to own the GLP repository as a whole.  Three things changed the arrangement since, all Udi's, all in `claude.md` and `CLAUDE.md`:

The projects have no Code session (2026-09-17).  Integration Code is the only session that runs code, and it carries out each owner's task by spawning a subagent in that owner's worktree, on that owner's branch; the subagent reads the owning paper itself, because coding is from the paper.  An owner's Cowork still writes every code task from its paper and is still its project's authority; what it no longer has is a Code session of its own to address.

Integration has two inboxes (2026-09-18).  `Integration_inbox.md` is Cowork's and `Integration-Code_inbox.md` is Code's, because one shared inbox gave the two sessions one bookmark: my receipt of 16:52 UTC buried a task addressed to Code, which Integration #2 Code found before it was lost.  Coordination adopted the split and put the session type into every project's receipt form.  Read Cowork's inbox from the last `Read: Integration #N Cowork` receipt; read Code's freely and never stamp it.

Both Integration sessions arm a ten-minute mail check at startup (2026-09-18), because a task written into an inbox is dead until Integration reads it.  Every other session reads its mail only when told to.

## The one ruling that governs the current work

**The same object is typechecked and then compiled, and there is no gap between the two** (Udi, 2026-09-18).  No clause of the compiled object is exempt from the checks, the linker's generated clauses included, and no diagnostic on a load path is a warning.

It came out of four days lost to a one-line defect: `anchor_friend/4`'s first clause passed an unbound tail, SRSW rejects exactly that, and SRSW had never run on any multi-module program because `compiler.dart:142` defaults it off to accommodate the linker's own generated clauses.  Two further sites of the same shape are open, and the instrument that would have caught all three --- a negative fixture per check on every load path --- is Integration's own item and not yet written.
